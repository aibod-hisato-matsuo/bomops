「https://baiten-gcp.web.app に admin でログインするとID/パスワード誤りで失敗する」との報告を調査。**パスワードやコードの問題ではなく、GCP プロジェクトの請求（billing）が無効化され backend 全体が停止していることが根本原因**と特定した。

**切り分け（ライブ probe）:**
- フロント SPA（Firebase Hosting・静的）→ `200`（正常配信）。
- backend API（Cloud Run `bomops-api`）→ `503` を **5/5 連続・数分間継続**（コールドスタートの一過性ではなく持続的障害）。
- `/api/v1/auth/token/`（ログイン）→ `503`。ログイン要求が Django 認証に到達せず、SPA が失敗を「ID/パスワード誤り」として汎用表示していた。

**gcloud 再認証:** 前セッションから約3か月経過しトークン失効。`gcloud auth login --no-launch-browser` は `!`（非対話）では EOF で失敗 → ユーザーが別ターミナル（実TTY）で認証完了（`matsuo@aibod.com`・cloud-platform スコープ）。

**根本原因チェーン（確定）:**
```
請求アカウント 013714-B49315-1CCF65 → CLOSED (OPEN: False)
   └─ プロジェクト baiten-gcp → billingEnabled: false
        ├─ Cloud SQL "bomops-pg" → SUSPENDED
        └─ Cloud Run "bomops-api" → 503 ("billing is disabled for this project")
             └─ /api/v1/auth/token/ 到達不可 → ログイン失敗
```
- Cloud Run サービス自体は `Ready=True`（最新 rev `bomops-api-00016-qdd`）だが、請求無効のためランタイムで全リクエスト 500/503。
- ログに `The request failed because billing is disabled for this project.` が 5分間隔で継続記録。
- `gcloud billing projects describe baiten-gcp` → `billingEnabled: false`。`gcloud billing accounts list` → 当該アカウント `OPEN: False`。
